# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

YapNotifier: a TeamSpeak 3 channel/talk-state overlay for GTA San Andreas / SA-MP, drawn with RmlUi (HTML/CSS-like documents). Two shipped artifacts from one CMake tree:

- `YapNotifierSA.asi` — x86 DLL loaded by an ASI loader (Silent's or CLEO's) from the GTA SA folder (or its `scripts/`); draws the overlay inside the game through its D3D9 device, from a hook on the game's frame.
- `YapNotifier.ts3_plugin` — TeamSpeak 3 client plugin (`yapnotifier_ts3_win64.dll` + `package.ini` zipped; x64, unlike the `.asi`); pushes the channel roster, per-client state and events to the `.asi` over localhost UDP.

Design specs: `docs/superpowers/specs/2026-10-03-samp-port-design.md` (the SA-MP port: frame hook, D3D9 renderer, input, SA-MP integration, address table; it supersedes the window/DirectComposition/DX11/raw-input parts of the older specs), `docs/superpowers/specs/2026-09-19-yapnotifier-design.md` (original, hook-era sections are obsolete) , `docs/superpowers/specs/2026-09-20-feature-port-design.md` (protocol v2, config, HUD; its ImGui rendering and window sections are obsolete) and `docs/superpowers/specs/2026-09-21-rmlui-conversion-design.md` (the RmlUi port: documents, data models; its backend/window notes are obsolete).

## Build

Requires MSVC (VS 2022, x86 and x64 toolsets) and CMake >= 3.24 (`winget install Kitware.CMake`). Deps (RmlUi 6.3 + its Win32 platform backend, FreeType, LunaSVG for the SVG plugin, TS3 plugin SDK headers) are fetched by CMake; no submodules. The first configure clones and builds them (a few minutes); they are built as static libs marked SYSTEM so `/W4` only applies to our sources.

```
cmake -S . -B build -A Win32 [-DYAPNOTIFIER_DEPLOY_DIR="C:/path/to/GTA San Andreas"]
cmake --build build --config Release
ctest --test-dir build -C Release        # runs test_parser + test_ui
```

Outputs: `build/Release/YapNotifierSA.asi`, `build/YapNotifier.ts3_plugin` (the x64 `ts3plugin/` sub-project, built through ExternalProject; standalone: `cmake -S ts3plugin -B build-ts3 -A x64`). With `YAPNOTIFIER_DEPLOY_DIR` set the `.asi` is copied there after every build. Everything compiles with `/W4 /permissive-`; keep it warning-free.

`YapNotifier.rc` carries the embedded Inter font (`YAP_FONT` RCDATA, variable: all weights load; `assets/InterVariable.ttf` is upstream Inter cut down by `tools/subset_font.py` to what FreeType-without-shaping can draw: Latin/Greek/Cyrillic/symbols, no GSUB/GPOS, opsz pinned to 14; rerun it on a new upstream release), `CHANGELOG.md` (`YAP_CHANGELOG`: the menu shows this version's section as "What's new" until the INI's `seen_version` matches), every UI file under `assets/ui/` as `UI_<PATH>` RCDATA (`icons/mic.svg` -> `UI_ICONS_MIC_SVG`; add a line when you add a file, `src/ui_files.cpp` serves them to RmlUi and falls back to disk) and version info.

**Releasing:** bump `YAP_VERSION` / `YAP_VERSION_NUM` in `shared/version.h` (feeds the `.rc`, the TS3 plugin, and the updater) and `Version` in `ts3plugin/package.ini` (CI fails if they differ), rename `## Unreleased` in `CHANGELOG.md` to `## <version> - <date>` (a tag build fails without that section; it becomes the release notes), then push a `v<version>` tag. The workflow builds, tests, and publishes a GitHub Release with `YapNotifierSA.asi` + `YapNotifier.ts3_plugin`; installed copies self-update from it. The asset name is `update::kAsiAsset`; the old FiveM builds (<= 0.4.1) look for `YapNotifier.asi`, so they never take an SA build.

`test_parser` covers the pure logic (datagram parser, config colour/enum parsing, template formatting, toast queue, roster rules, updater helpers). `test_ui` loads `hud.rml` / `menu.rml` through the real `hud::init` / `menu::init` with a null renderer, runs demo frames at every anchor and fails on any RmlUi warning (bad RCSS, unbound data variable, broken template). Run it after touching anything in `assets/ui/` or the data models. The in-game overlay (frame hook, D3D9 renderer, input) and the TS3 plugin can only be verified in-game / in-client. Runtime log: `<asi folder>/YapNotifier.log`; settings: `<asi folder>/YapNotifier.ini`; profiles: `<asi folder>/YapNotifier.profiles/*.ini`. In-game: **INSERT** opens the config menu (tabs: Status, Layout, Roster, Indicators, Notifications, Chat, Users, Channel, Profiles, Keys); **HOME** (`hide_key`) toggles `hud_hidden`, which skips the HUD's render and mouse input but keeps syncing it. Both hotkeys are polled on the init thread from `overlay::hotkeys()` (live `g_cfg`, published each frame; 0 while the Keys tab is capturing; `Hotkeys::blocked` while SA-MP has chat/a dialog open, and they only fire while the game is the foreground window). The Keys tab takes the raw VK code in the window subclass on key-up, since RmlUi key events don't carry it. **Demo mode** (Status tab) renders a fake roster + scripted events without TeamSpeak. There is no eject key; the plugin lives for the whole process.

## Architecture

Data flows one way: TeamSpeak -> plugin -> UDP -> `.asi` listener thread -> atomic snapshot + event queue -> game thread (render).

- **Wire format v2** (`shared/yap_protocol.h`, included by both sides): one UDP datagram to `127.0.0.1:25640` carrying the *complete* state of the active TS tab: `YAP2\n`, then tab-separated `S` (connection + server name), `C` (channel id/parent/name), `U` (one per client in the own channel: clid, flags bitmask, unique id, contact nickname, display name) and `E` (one-shot events: join/leave/switch/conn/whisper/chat) lines. The last field of a line is the remainder of the line, so free text goes last. Sent on every change and as a 1 s heartbeat (heartbeats carry no `E`); the `.asi` treats 3 s of silence as "plugin gone". `YAP1` (talk-only) is still accepted and flagged `legacy` so an auto-updated `.asi` keeps working with an old plugin. Change the format in the header, the plugin's `send_locked`, `parse_datagram`, and `tests/test_parser.cpp` together.
- **TS3 plugin** (`ts3plugin/plugin.cpp`): C++ over the C SDK; exports `ts3plugin_*`. Mirrors only the active tab (`currentServerConnectionChanged`). Every roster-affecting callback runs `resync_locked()` (full re-read of the own channel via `getChannelClientList` + client properties); talk/whisper state lives in two sets and is OR'd in at send time. Move callbacks emit join/leave/switch events with channel names; text/poke callbacks emit chat events (truncated to `kMaxChatChars`, always `return 0` so TS still shows them). Friends come from the client's `settings.db` via `ts_contacts.cpp` / `sqlite_read.cpp` (MIT, copied from TeamSpeak3-Reshade-overlay, see `assets/LICENSE-tsro.txt`).
- **.asi threads:**
  - *Init* (`src/main.cpp`): spawned from `DllMain` (never work under the loader lock). Loads the INI, starts the overlay and the listener, runs the updater, then polls the hotkeys forever.
  - *Game thread* (`src/game.cpp`, `src/overlay.cpp`, `src/render_d3d9.cpp`): `game.cpp` patches the `CFont::DrawFonts` call at 0x53EBB1 in `DllMain` (verified as 1.0 US + an `E8` call; chains the previous target), so the overlay runs inside GTA's frame on GTA's main thread and all RmlUi calls happen there. `overlay::frame` initialises RmlUi lazily (two contexts, HUD and menu, with `RmlUi_Platform_Win32` for input/clipboard; documents served from resources by `src/ui_files.cpp`, fonts registered as family `Yap`) and per frame runs drain `ts::drain_events` into `hud::feed` -> `hud::sync` + `menu::sync` refill the data models -> `Context::Update/Render` through `render_d3d9.cpp` (RmlUi `RenderInterface` on the game's D3D9 device: fixed-function pipeline, managed textures, `DrawIndexedPrimitiveUP`; a per-frame `D3DSBT_ALL` state block plus a manual transform save/restore keep RenderWare's state cache valid; clip masks use the stencil buffer with a scissor fallback; no device-reset handling is needed). Input: `game::subclass_window` installs a window subclass above SA-MP's (it waits for `MainWndProc` 0x747EB0 to be replaced, with 3 s / 10 s fallbacks) and routes messages to RmlUi only while the menu is open, swallowing keyboard and mouse; the cursor/camera lock is `samp::set_cursor` on SA-MP 0.3.DL R1 (`src/samp.cpp`, entry-point RVA `0xFDB60`, anything else gets no SA-MP integration) else `game::lock_input` (SA-MP's own byte patches, verified before writing). `samp::typing()` is published each frame as `Hotkeys::blocked`. Faults in game/SA-MP memory reads and calls run under SEH. All RCSS sizes are `dp`; `cfg.scale` is the HUD context's dp ratio, the menu context stays at 1 so the Scale slider never resizes the menu.
  - *Listener* (`src/teamspeak.cpp`): binds the UDP port, parses datagrams, publishes immutable `Snapshot`s through one `std::atomic<std::shared_ptr<const Snapshot>>` and pushes `Event`s into a mutex-guarded queue (cap 64). The render thread only ever calls `ts::snapshot()` / `ts::drain_events()`.
- **HUD** (`src/hud.cpp` + `assets/ui/hud.rml|hud.rcss`): `hud::sync` fills the `hud` data model (title, `rows[]` with leading/trailing icons, `toasts[]`, `chat[]`, notice; colours as `#RRGGBBAA`, sizes as `<n>dp`) every frame and the document renders it with `data-for` / `data-style-*`; nothing in it is hit-testable except in **edit mode** (`hud::edit(&cfg)`, on while the menu is open): `body.edit` makes every block visible with a grip label and `drag: drag`, and a drag writes the new offset straight into the `Config` via `roster::drag_offset` (right/bottom anchors invert the delta), so the menu's sliders follow; the window subclass forwards mouse presses the menu did not take (and all moves/releases) to the HUD context for this. Icons are white SVGs in `assets/ui/icons/` named after `config::to_string(IconShape)`, tinted with `image-color` (`src/icons.cpp` is just the shape->path map). Anchoring is 9-point (`Anchor`) + px offsets, applied by `place()` as `left/right/top/bottom` + `translate(-50%)`; long names are clipped (`overflow: hidden`) rather than ellipsised. Pure rules live in `src/roster.cpp` (visibility, sort, state->colour/icon priority, speaking envelope) and `src/notify.cpp` (template formatting, toast queue, chat filtering) so `test_parser` can pin them.
- **Config** (`src/config.cpp`): flat `[YapNotifier]` INI via the Win32 profile API; one `visit()` field list drives load and save. Colours are `#RRGGBBAA` (`0` = unset). Per-user overrides live in `[user:<unique id>]` sections, per-channel in `[channel:<id>]`. Profiles are plain copies of the INI. `demo` is never saved.
- **Menu** (`src/menu.cpp` + `assets/ui/menu.rml|theme.rcss`): `menu.rml` is a `<tabset>` of RmlUi form controls bound through the `cfg` data model straight to the live `Config` members (`m.Bind("scale", &cfg.scale)`, names = ini keys; enums and `Color` bind as numbers; `ind`/`notif` are `std::array`s bound as data arrays; per-user/channel overrides are rows holding a pointer into the map). Buttons are `BindEventCallback`s (`save`, `reload`, `reset`, profiles, overrides). Edits apply immediately, Save writes the INI; only `font_file` needs a relaunch. Colours use the custom `<colorpicker>` element (`src/colorpicker.cpp`: swatch that expands into an HSV square + hue/alpha bars, `optional` = 0 means unset, speaks `data-value` via a `change` event). `theme.rcss` styles every widget part (RmlUi has no default stylesheet); its light palette follows `DESIGN.md` and `body.dark` (ini `dark_theme`, Status tab, set by `menu::sync`) swaps in the dark one; the HUD toasts read the same flag in `sync_toasts`.
- **Updater** (`src/update.cpp`, runs on the init thread): `GET api.github.com/repos/<YAP_GITHUB_REPO>/releases/latest` (`YAP_GITHUB_REPO` from `shared/version.h`) via WinHTTP, compares `tag_name` to `YAP_VERSION`, downloads the `YapNotifierSA.asi` asset (`update::kAsiAsset`), verifies it against the asset `digest` (SHA-256 via BCrypt), then renames the running `.asi` to `.asi.old` and drops the new file in place. Windows allows renaming a mapped DLL, so the swap is immediate and takes effect on the next GTA SA start. `.asi.old` is deleted on the following launch. `auto_update=0` in the INI checks but does not install. Status surfaces through `update::notice()` as a 20 s banner and a line in the menu.

Failure policy everywhere: log and go dormant, never crash the game or the TS client.
